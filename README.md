# COMPSYS 303 Assignment 1 - SCCharts traffic-light controller

**Version A = simulator** (Timed SCCharts in KIELER, time from `deltaT`).
**Version B = board** (the same controller on a Nios II on the DE2-115, time from a hardware timer).

Group 14 members: **Harold Tien** (`thar970`) and **Lucas Young** (`wyou790`).

**Selecting the timing version:** there is no switch for it. The brief allows separate charts, and
each task exists as a Version A chart (clocks, run in the KIELER simulator) and a Version B chart
(counts the Nios II timer event, runs on the board). Same states, regions and LED words in both;
`VersionB/evidence/diff_A_B.py` checks that only the timing differs. **Selecting the task:** the
`task` input in the simulator, SW1..SW0 on the board (table below).

## Running Version A (simulator)

1. VS Code with the KIELER extension (`kieler.keith-vscode`), open a Version A `.sctx`.
2. *Simulate* with the netlist C simulation (*Netlist-based Simulation (C)*) in **Dynamic** mode, or step manually.
3. `deltaT` is in **seconds**. Inputs: `task` (1-4), `NSraised`, `EWraised`, `configChar`/`configValid`
   (Task 3, one ASCII character per tick, only while `configReady`; packet values in milliseconds, see
   below), `vehicleButton` (Task 4, each rising edge toggles enter/leave). See `TASK3.md` and `TASK4.md`
   for worked step sequences.

## Running Version B (DE2-115)

**Program the FPGA**

* Submission image: program the `.pof` into the EPCS64 configuration flash (Active Serial).
  The `.pof` holds only the FPGA hardware: after power-up the FPGA loads from flash without
  programming, but the Nios II program lives in SDRAM, so the lights only cycle after
  `nios2-download -g traffic_b.elf`.
  Sequence: power-cycle -> FPGA loads from flash without programming -> `nios2-download` the
  `.elf` -> lights cycle.
* Development image: `output_files/COMPSYS303_Lab1_time_limited.sof` (Quartus Lite, OpenCore Plus).
  It only runs **while tethered**: keep `nios2-configure-sof` (or the Quartus Programmer OpenCore Plus
  window) open the whole time.

**Build** (Nios II Command Shell, no edits needed - verified from a fresh clone)

```
cd VersionB/COMPSYS303_Lab1/software/traffic_b_bsp
nios2-bsp-generate-files --settings=settings.bsp --bsp-dir=.
make
cd ../traffic_b
make
```

or in Nios II SBT Eclipse: *File > Import > Existing Projects into Workspace*, root `software`, tick
`traffic_b` and `traffic_b_bsp` (no copy), *Generate BSP*, *Build*.

**Download and run**

```
nios2-configure-sof output_files/COMPSYS303_Lab1_time_limited.sof    (time-limited image only; leave it open)
nios2-download -g software/traffic_b/traffic_b.elf
nios2-terminal
```

Rebuilding the hardware: `qsys-generate nios2_system.qsys --synthesis=VERILOG`, then compile
`COMPSYS303_Lab1.qpf` (a full licence gives `COMPSYS303_Lab1.sof` without `_time_limited`).

## Board mapping

| Board | Function |
|---|---|
| SW1..SW0 | Task: `00` Task 1, `01` Task 2 (pedestrians), `10` Task 3 (configuration), `11` Task 4 (camera + pedestrians). A change takes effect at the next all-red. |
| KEY0 | NS pedestrian request |
| KEY1 | EW pedestrian request |
| KEY2 | Vehicle: each press toggles enter / leave (Task 4) |
| KEY3 | Reset of the Nios II system (restarts at G-R) |
| LEDR0 / LEDR1 / LEDR2 | NS green / yellow / red |
| LEDR3 / LEDR4 / LEDR5 | EW green / yellow / red |
| LEDR6 / LEDR7 | NS walk / EW walk |
| RS-232 (UART) | Task 3 packets at **115200 8N1** (optional: needs a DB9 serial cable) |
| JTAG UART (`nios2-terminal`) | Console: every LEDR change with its measured duration, ticks and timer events; Task 4 messages (`Camera activated`, `Snapshot taken`, `Vehicle left`). Also accepts Task 3 packets typed into `nios2-terminal` (USB-Blaster cable only) |

**Task 3 packet:** `#,#,#,#,#,#[\r]\n` - six integers of 1-4 digits in **milliseconds** (1..9999),
comma-separated, ending with LF (CR is ignored), in the order t1..t6 = G-R, Y-R, R-R, R-G, R-Y, R-R.
Example: `8000,3000,1000,8000,3000,1000` + LF; the defaults are `6000,2000,500,6000,2000,500`. A valid
packet is applied at the next all-red; an invalid one (wrong field count, empty field, 5 digits, any other
character, or a **0** field, which would skip a yellow or all-red) is rejected and the lights keep waiting.
Version B rounds each value up to whole timer events (10 ms), e.g. 1234 ms -> 124 events.
Same packets in both versions.

Default timing: G 6 s, Y 2 s, all-red 0.5 s, walk 4 s, camera dwell 1 s; one timer event every 10 ms
(`TIMER_MS` in the chart = `TIMER_PERIOD_MS` in `main.c`).

## Known limitations

* The `.pof` contains only the FPGA hardware. The Nios II reset vector is in SDRAM
  (`0x00800000`) and the program (about 98 KB) does not fit the 30 KB on-chip RAM, so after
  power-up the `.elf` must be downloaded over JTAG. Future work: boot the software from flash
  (an EPCS flash controller plus a boot copier in the Qsys system).
* The time-limited `.sof` needs the JTAG tether; if the tether is interrupted the Nios II stops (re-configure).
* JTAG `printf`: with no console attached the HAL buffers about 2 KB of output; after that output is lost
  or `printf` can briefly delay the loop. The lights keep their timing in the tested 50 s without a console.
* Task 3 values are limited by the 4-digit field to 9.999 s per phase.
* Task 3 bytes are read from RS-232 first, then from the JTAG console. Send a packet on one port
  at a time: two packets arriving together would have their bytes mixed.
* The console's microsecond times wrap after 85.9 s (32-bit timer at 50 MHz); a single phase longer than
  that (a Task 3 hold) is printed 85.9 s short. Timer-event counts are always exact.
