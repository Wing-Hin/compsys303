## Demo in five minutes

1. Board on, USB-Blaster in the BLASTER port, RUN/PROG on RUN, SW1..SW0 = `00`.
   Double-click `VersionB\run_board.bat`; **keep the tether window open** (closing it stops the Nios II).
2. **Task 1** (`00`): the console shows each phase as 600 / 200 / 50 timer events (6 / 2 / 0.5 s).
3. **Task 2** (`01`): KEY0 -> NS walk light (LEDR6) for 4 s at the next NS green; KEY1 -> EW walk (LEDR7).
4. **Task 3** (`10`): the lights hold at all-red. In the console type `8000,3000,1000,8000,3000,1000`
   and **Ctrl+J** (no echo): the cycle resumes with 8 / 3 / 1 s. `6000,2000,500,6000,2000,500` restores
   the defaults; `1,2,3` or a 0 field is rejected.
5. **Task 4** (`11`): KEY2 in a green (car enters) -> `Camera activated` at the yellow and
   `Snapshot taken` 1 s later; KEY2 again -> `Vehicle left`.
6. **Version A:** open `VersionA/TrafficLight_VersionA.sctx` in KIELER, Netlist-based Simulation (C),
   Dynamic mode, `task = 1`: the phases change exactly at 6 / 2 / 0.5 s.

## Programming files

The submission contains `VersionB/COMPSYS303_Lab1/output_files/COMPSYS303_Lab1_time_limited.sof`
and **no `.pof`**.

* **Why there is no `.pof`.** We compile with Quartus Prime 18.1 **Lite Edition**, and the Lab 1
  system uses the **Nios II/f** core (`impl = Fast` in `nios2_system.sopcinfo`), which needs a Nios II
  licence. Without one, Quartus builds the core under OpenCore Plus (Intel FPGA IP Evaluation Mode):
  the only output is a time-limited `*_time_limited.sof` that runs only while its OpenCore Plus session
  is active over JTAG (the tether). A `.pof` cannot be made from it.
* **A `.pof` would not hold the program anyway.** A `.pof` only configures the FPGA from the EPCS64
  flash. The Nios II reset vector is in SDRAM (`0x00800000`) and the program (about 98 KB) does not
  fit the 30 KB on-chip RAM, so after every power-up `traffic_b.elf` has to be downloaded over JTAG
  in any case.
* **It is the tested build.** Every board log in `evidence/board_logs/` used this file: SHA-256
  `d11cd8f5e0924dc9990390fe9c7be95e8af5f9531cff8bd0cc3a2c47c62e6a10`, Quartus checksum `0x008CFF92`,
  assembled Fri 21 Aug 2026 14:38:23 (NZST). It was compiled from the Platform Designer generation of
  7 Aug 2026 17:34:53, generation ID `1786080893`, which is the `AUTO_GENERATION_ID` in the
  `nios2_system.sopcinfo` in this zip (and the `GENERATION_ID` in that compile's `.sld`/`.jdi`).

**Steps** (Quartus Prime 18.1, Lite is enough, with the Nios II EDS):

1. Board powered, USB-Blaster cable in the BLASTER port, RUN/PROG switch on RUN.
2. Quartus **Programmer** (*Tools > Programmer*): *Hardware Setup* -> **USB-Blaster**, mode **JTAG**.
3. *Add File* -> `VersionB/COMPSYS303_Lab1/output_files/COMPSYS303_Lab1_time_limited.sof`, tick
   *Program/Configure*, *Start*; wait for 100 % (Successful).
4. The **OpenCore Plus** dialog opens. **Keep it open** the whole time: closing it (or unplugging the
   cable) stops the Nios II.
5. Nios II Command Shell, in `VersionB/COMPSYS303_Lab1/software/traffic_b`:
   `nios2-download -g traffic_b.elf`
6. `nios2-terminal` for the console (Ctrl-C leaves it; the lights keep running).

Instead of 5-6, in Nios II SBT Eclipse: right-click `traffic_b` -> *Run As* -> *Nios II Hardware*.

**One command:** `VersionB\run_board.bat` does steps 2-6 with `quartus_pgm` (the tether runs in its
own window: keep it open), `nios2-download -g` and `nios2-terminal`. It finds Quartus through
`QUARTUS_ROOTDIR` (or `C:\intelFPGA_lite\18.1`) and needs `traffic_b.elf` (included, or build it as
below). An optional argument selects another cable name (`jtagconfig` lists them).

## Board mapping

| Board | Function |
|---|---|
| SW1..SW0 | Task: `00` Task 1, `01` Task 2 (pedestrians), `10` Task 3 (configuration), `11` Task 4 (camera + pedestrians). A change takes effect at the next all-red. |
| KEY0 | NS pedestrian request |
| KEY1 | EW pedestrian request |
| KEY2 | Vehicle: each press toggles enter / leave (Task 4) |
| KEY3 | Reset of the Nios II system (restarts at G-R) |
| LEDR0 / LEDR1 / LEDR2 | NS green / yellow / red |
| LEDR3 / LEDR4 / LEDR5 | EW green / yellow / red |
| LEDR6 / LEDR7 | NS walk / EW walk |
| RS-232 (UART) | Task 3 packets at **115200 8N1** (optional: needs a DB9 serial cable) |
| JTAG UART (`nios2-terminal`) | Console: every LEDR change with its measured duration, ticks and timer events; Task 4 messages (`Camera activated`, `Snapshot taken`, `Vehicle left`). Also accepts Task 3 packets typed into `nios2-terminal` (USB-Blaster cable only) |

**Task 3 packet:** `#,#,#,#,#,#[\r]\n` - six integers of 1-4 digits in **milliseconds** (1..9999),
comma-separated, ending with LF (CR is ignored), in the order t1..t6 = G-R, Y-R, R-R, R-G, R-Y, R-R.
Example: `8000,3000,1000,8000,3000,1000` + LF; the defaults are `6000,2000,500,6000,2000,500`. A valid
packet is applied at the next all-red; an invalid one (wrong field count, empty field, 5 digits, any other
character, or a **0** field, which would skip a yellow or all-red) is rejected and the lights keep waiting.
Version B rounds each value up to whole timer events (10 ms), e.g. 1234 ms -> 124 events.
Same packets in both versions.

Default timing: G 6 s, Y 2 s, all-red 0.5 s, walk 4 s, camera dwell 1 s; one timer event every 10 ms
(`TIMER_MS` in the chart = `TIMER_PERIOD_MS` in `main.c`).

## Known limitations

* No `.pof` (see *Programming files*): the FPGA is programmed over JTAG with the time-limited `.sof`,
  and the program always has to be downloaded over JTAG because it runs from SDRAM. Future work: a
  full-licence (or Nios II/e) build for a `.pof`, and booting the software from flash (an EPCS flash
  controller plus a boot copier in the Qsys system).
* The time-limited `.sof` needs its OpenCore Plus JTAG tether; if it is interrupted the Nios II stops
  (re-configure).
* JTAG `printf`: with no console attached the HAL buffers about 2 KB of output; after that output is lost
  or `printf` can briefly delay the loop. The lights keep their timing in the tested 50 s without a console.
* Task 3 values are limited by the 4-digit field to 9.999 s per phase.
* Task 3 bytes are read from RS-232 first, then from the JTAG console. Send a packet on one port
  at a time: two packets arriving together would have their bytes mixed.
* The console's microsecond times wrap after 85.9 s (32-bit timer at 50 MHz); a single phase longer than
  that (a Task 3 hold) is printed 85.9 s short. Timer-event counts are always exact.
